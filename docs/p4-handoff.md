## 二、OL-07：设计接入与独立检查

### 1. 需求接纳

`RequirementBridge` 会在服务端重新校验原始需求、内容指纹、版本和确认目标，并核对：

- 确认人是否位于受信授权名单；
- 确认记录是否来自受信上游登记；
- 来源编号是否有效；
- 确认依赖是否仍然有效；
- 输入是否属于人工构造样例。

这些授权资料由可信服务端或上游系统提供，不能把上传文件里的姓名当成身份证明。

构造样例必须显式启用 `allow_synthetic=True`，并持续保留构造标识，不会变成真实人工批准。

### 2. 设计生成

`AthenaDesigner` 复用 P2 的 `AgentRunner`，读取完整需求，输出符合 `DesignContent` 的结构化设计。

设计编号、版本、指纹和需求引用由程序生成。输出不合格式时明确报错，不会静默套用校园样例。

### 3. 设计审查

`DesignReviewer` 结合程序检查与 Momus 独立模型调用：

- 程序检查来源、覆盖、范围、结构和版本；
- Momus 检查含义、遗漏与越界；
- 报告交给 P2 的 `CommonReviewer` 登记。

模型写出“通过”不能覆盖程序发现的阻断问题。

通用业务使用 `generic` 检查配置；只有显式选择 `campus-v1.3` 时，才启用校园案例专项检查。

### 4. 有限返修

`DesignWorkflow.generate` 对同一已接纳需求保持重复调用结果一致，重复生成不会重新扣费或重置返修额度。

同一服务中的并发生成会串行核验，返回结果与内部记录相互隔离；调用方修改返回对象不会改写已登记设计。查看旧设计时只返回该版本自己的报告，不附带新版本的批准记录。

每个需求基线最多一次内容返修，自动修复和显式 `revise(..., findings=[...])` 共用这一次机会。改版后旧审查、旧确认不能用于新设计。

### 5. 人工批准与规划衔接

| 接口 | 用途 |
| --- | --- |
| `bind_approval(bus, req, ds)` | 向 P3 命令总线注册设计、报告和版本检查 |
| `request_approval(gate, req, ds)` | 使用 P3 原有人工等待、恢复和接纳关口 |
| `require_approved(req, ds)` | 确认当前版本已批准且报告仍有效 |
| `plan(req, ds, planning_workflow)` | 检查批准后调用 P2 规划流程 |
| `project(req, ds)` | 返回来源、设计、追踪和当前确认信息 |

设计批准可以先于任务计划。设计阶段可使用 `CommandBus(RunContext(design_stage_run))`；尚未接入审核后的计划和调度器时，只允许已登记的设计批准动作。

没有另造模型提供方、独立审查引擎或人工确认状态机。设计服务中的当前版本、确认和返修记录仍需由宿主在跨进程恢复时重建，本部分不代表 P5 的持久化恢复已经完成。

## 三、OL-08：真实执行与独立验收

### 1. 建立执行适配器

使用：

~~~python
LocalPythonExecutor(scheduler, evidence_root, HephaestusImplementer(runner))
~~~

适配器复用现有调度器、执行许可、请求账本和角色调用能力。

### 2. 提前冻结验收定义

可信服务端使用 `FrozenAcceptance.freeze(task, checks)` 冻结独立脚本，脚本编号必须与 `task.checks` 完全对应。

然后通过 `register_task` 登记，必须先登记再派发。Hephaestus 无权修改这些脚本、预期值或夹具。

### 3. 核对实际输入

可选的 `context` 将已批准的需求、设计或计划编号映射到完整正文，派发前检查正文与指纹是否一致。

前驱任务不仅需要显示为“已验收”，还必须存在有效回执与实际工件。适配器重新计算输入文件指纹，把已验收输入复制进独立工作目录；有冲突或缺少实际字节时拒绝执行。

### 4. 取得许可后派发

使用 `scheduler.dispatch(task_id, executor)`。

真实工具运行必须显式使用 `real_tool` 或 `real_model` 运行模式。适配器的预检不能自行取得调度许可。

### 5. 查询执行状态与证据

| 接口 | 返回内容 |
| --- | --- |
| `query(attempt_id)` | 执行中、成功、失败、结果未知或已取消 |
| `query_receipt(attempt_id)` | 结构化执行回执 |
| `project(attempt_id)` | 可供接口层直接返回的字典 |
| `wait(attempt_id, timeout)` | 供脚本和测试等待结果 |

回执包括请求与尝试编号、模型模式、工具模式、修改差异、实际检查输出、通过项，以及输入、实现、测试和夹具指纹。

回执还包含 `run_id`、重复提交的操作编号、实际 Python 进程次数 `tool_invocations`，以及已保存的独立复核报告 `review`。同一证据目录中，不同运行的回执按运行编号隔离，模型请求也绑定运行编号。

需要同时读取任务状态和验收详情时，使用验收服务的 `project(task_id, attempt_id=None)`：`runtime` 是 P3 的权威状态，`execution` 是完整执行回执，`review_requests` 列出独立复核请求及待核对标记；`is_current` 表示是否仍为当前执行代际。该查询不会触发模型调用。

### 6. 独立验收

使用：

~~~python
ArtifactAcceptanceService(executor, ArgusReviewer(runner)).collect(task_id, attempt_id)
~~~

验收服务重新核对工件与证据，调用 P2 的独立复核能力，再在调度锁内核对当前尝试、执行代际与报告，最后委托 Zeus 更新验证状态与任务状态。

程序检查失败或 Argus 拒绝都不能变成“已验收”。模型复核不可用、预算耗尽时，产物继续保持未验证状态。

同一验收服务会串行处理并发收集。重复收集已验收结果复用已保存的报告，重新核验版本与证据，不重复调用模型或追加验收事件。重启后需要宿主恢复相应 P3 状态与许可映射，才能复核既有结果；不会仅凭磁盘回执把任务恢复成已验收。

已有 Argus 请求但没有完整报告时，继续保留待核对状态；P5 应核实请求结果并显式决定后续处理，不能把再次调用 `collect` 当作自动重试。

### 7. 取消与未知结果

P5 优先使用验收服务的 `cancel(task_id)`；也可以先调用适配器 `cancel`，取得确定终态后再处理调度状态。

**直接调用 `Scheduler.cancel` 不能停止实际进程。** 无法确认终止时，保留未知状态与资源，不能当成已经停机。

执行器重启后，无法核实的在途工作保持 `outcome_unknown`。P4 不猜测进程已死，也不代替 P5 重建完整调度器。

### 8. 预算与记录

模型调用使用 P2 账本，并累计进 P3 的 `Run.calls_used`，结果未知的调用也计入。

工具账本保存于 `evidence_root/requests.json`，记录受控本地执行请求。每份执行回执同时列出实际运行的 Python 检查进程。执行记录的 `call_count` 按实际启动进程数计数，模型输出或写入校验先失败时为零；它与工具请求预算、模型调用预算是不同计数。恢复时复用既有记录，不盲目重发。

## 四、执行范围

本部分是一种可信本地执行适配器，适用于经过审查的课程代码，不是生产级恶意代码隔离平台。

- 写入前校验全部变更；只允许任务范围内的 Python、JSON、Markdown 和文本文件。
- 实现代码不允许任意系统、进程、网络导入、动态执行、私有反射或通配导入。
- 已登记的导入仅包括 `math` 和 `threading` 的 `Lock`／`RLock`。
- 使用 `shell=False`、隔离解释器参数、时间与输出上限，并减少环境变量，不继承模型密钥。
- 独立检查材料位于实现目录之外。
- 可信验收脚本可以使用标准库 `unittest` 检查实际实现。

Momus 的测试任务与 Hermes 的联调、记录任务采用只读检查方式：不调用实现模型，只运行冻结脚本，并在任务范围内写入检查报告。Argus 绑定真实执行者作为产物作者。其他角色与任务类型组合在派发前拒绝。

本期不包含自由命令平台、多语言执行、容器集群、生产部署、网页接口、正式界面、Nyx 或长期记忆。

模拟模型加真实工具是一种单独的验证级别，不能描述成真实在线模型已经通过评测。

## 六、P5 与 P6 怎样接棒

| 接棒人 | 直接复用 | 仍需自己完成 |
| --- | --- | --- |
| P5 恢复模块 | P2 账本、P3 许可与代际、P4 查询及取消回执 | 恢复编排、有限重试、修复子任务、人工处置和跨进程重建 |
| P5 接口层 | 设计投影、执行回执、独立报告服务、P3 状态与命令结果 | HTTP 路由、错误格式、事件补取和录制回放 |
| P6 界面 | P5 提供的数据接口，以及 P2／P3／P4 的真实产物和证据 | 四视图、统一操作面板和浏览器联调 |

接入时保留以下含义：

1. 执行成功不等于任务已验收；界面以服务端任务状态为准。
2. 无法确认取消时继续显示待核对，不能显示全部已停止。
3. 改版或修复后旧检查、旧报告不能用于新产物。
4. 显示模拟模型、真实工具、真实模型的区别。
5. 原分工规定 P5 在 P4 的合并申请进入主分支后正式接棒，P6 再接 P5 的接口。提前读取分支和准备代码不等于主分支已更新。
